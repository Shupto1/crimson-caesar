What is a Microprocessor?

A microprocessor is a sophisticated digital integrated circuit that serves as the "brain" of a computer system. It is fundamentally a multipurpose, programmable, register-based electronic device that performs three primary functions:

  • Read: Fetches binary instructions from memory location by location in sequence
  • Process: Executes these instructions by manipulating data using the processor's internal arithmetic and logic units
  • Output: Produces results and sends them to memory, I/O devices, or displays
⚡ Key Insight: A microprocessor contains ONLY the CPU (processing logic). It has NO built-in memory or I/O devices. All these components must be added externally by the system designer.

Historical Context

Computing evolved through several generations before reaching microprocessors:

  • 1930s-40s: Mechanical calculating devices using relays
  • 1950s: Vacuum tubes (immediately replaced by transistors - faster, smaller, more reliable)
  • 1960s: Introduction of integrated circuits; minicomputers became possible
  • 1970s: Birth of personal computers with affordable microprocessors

What is a Microcomputer?

A microcomputer is a small and relatively inexpensive computer with a central processing unit (CPU) made up of a microprocessor. Examples include smartphones, laptops, and tablets.

📌 Applications
  • Households & Personal Use: Browsing the internet, watching videos, and playing games.
  • Education: Wide use in teaching, research, and administration.
  • Business & Office Use: Creating and editing documents, spreadsheets, etc.
  • Engineering & Science: Simulations, data analysis, and technical visualization.
  • Industrial Control: Process control, automation, and monitoring.
✅ Advantages
  • Cost: Varies depending on user requirements.
  • Portability: Devices like smartphones, laptops, and tablets are highly portable.
  • Energy Efficiency: Requires less power than larger computer systems.
  • Rapid Advancements: Constantly evolving with new technologies.
  • Increased Productivity: Allows efficient work using word processing and related tools.
⚠️ Disadvantages
  • Performance: Relatively low when compared with mainframe or supercomputers.
  • Security: Relying on internet connectivity makes the system vulnerable to threats.
  • Addiction: Vulnerable to excessive browsing, social media, and gaming.
  • Storage Capacity: The default built-in storage is very less.
  • Health Issues: Excessive use can cause structural health problems and posture/eye strain.

Microprocessor vs Microcontroller: Detailed Comparison

Microprocessor (μP)
  • CPU Only: Contains only processing unit
  • No Built-in Memory: RAM/ROM must be added externally
  • No Timer: Timing circuits added separately
  • No I/O Ports: Cannot directly connect peripherals
  • Complex Instruction Set: Many addressing modes
  • Higher Power Consumption: Needs more power supply circuitry
  • Examples: Intel 8086, 80386, Pentium, i7
Microcontroller (μC)
  • Complete System on Chip: CPU + Memory + I/O
  • Inbuilt Memory: RAM and ROM integrated
  • Inbuilt Timer: Timing functions available
  • I/O Ports Available: Can directly interface peripherals
  • Serial Port Built-in: Can communicate via UART
  • Low Power Consumption: Designed for embedded systems
  • Examples: Intel 8051, PIC, ARM Cortex

5 Generations of Microprocessor Evolution

1st Generation (1971-1973): PMOS Technology

  • Intel 4004 (1971): First microprocessor, 4-bit, 10 µm technology, 108 kHz, 2,300 transistors
  • Intel 8008 (1972): 8-bit processor, 20 kHz faster
  • Intel 8080 (1974): 8-bit, improved instruction set, 2 µm technology
  • Characteristics: Non-compatible with TTL, slow speed (max 1 MHz), low cost
  • Package: 40-pin DIP (Dual Inline Package)

2nd Generation (1974-1978): NMOS Technology

  • Motorola 6800, 6809: Competing 8-bit processors
  • Intel 8085: Improved 8-bit with inbuilt clock, reset circuitry
  • Zilog Z80: Popular 8-bit with better instruction set
  • Speed: Up to 3 MHz (faster than 1st gen)
  • Technology: NMOS - faster, higher density, TTL compatible
  • Significance: Beginning of efficient 8-bit processors era

3rd Generation (1978-1980): HMOS Technology - **IMPORTANT FOR COURSE**

  • Intel 8086 (1978): 16-bit processor, 3 µm technology, 29,000 transistors
  • Zilog Z8000: Competing 16-bit architecture
  • Characteristics:
    • 16-bit data path with minicomputer-like performance
    • 16-bit arithmetic and pipelined instruction processing
    • Segmented memory (1 MB addressable space)
    • Faster than 2nd generation (5-10 MHz)
    • ~250,000 transistors
    • HMOS technology: higher density MOS
  • Why Important? 8086 is the focus of this entire course!

4th Generation (1981-1995): HCMOS Technology

  • Intel 80386 (1985): First 32-bit processor, 100,000 transistors minimum
  • Intel 486 (1989): Integrated floating-point unit, 12 million transistors
  • Motorola 68020/68030: Competing 32-bit processors
  • Speeds: 20-100 MHz range
  • Technology: HCMOS - high-speed CMOS, lower power than NMOS
  • Significance: Move to 32-bit computing, virtual memory support

5th Generation (1993-present): Pentium & Beyond

  • Pentium (1993): 60-300 MHz, 3.2-45 million transistors
  • Pentium Pro (1995): 166-200 MHz, 5.5 million transistors
  • Pentium II (1997): 233-450 MHz, 75 million transistors
  • Pentium III (1999): 450-1000 MHz, 9.5-28 million transistors
  • Pentium 4 (2001): 1.4-3.2 GHz, 42-55 million transistors
  • Modern Era: Multi-core, GHz speeds, billions of transistors

Basic Microprocessor System Architecture

Three-Bus Architecture of Microprocessor System

Address Bus Details

  • Direction: Unidirectional (from CPU only)
  • Purpose: Selects which memory location or I/O port to access
  • Width: Typically 8 to 32 bits (8086 uses 20 bits)
  • Calculation: N-bit address bus = 2^N total addressable locations
  • Example: 20-bit address bus (8086) = 2^20 = 1,048,576 addresses = 1 MB
  • Representation: Always in binary internally, shown as hexadecimal for convenience

Data Bus Details

  • Direction: Bidirectional (both CPU→Memory and Memory→CPU)
  • Purpose: Transfer data between processor, memory, and peripherals
  • Width Determines: How much data can transfer simultaneously
  • 8-bit Bus: 256 different values (0-255)
  • 16-bit Bus: 65,536 different values (0-65535) - Used in 8086
  • Speed Impact: Wider bus = more data per cycle = better performance

System Bus Architecture

Data is transferred between different components of a computer system using physical wires called buses. The primary bus types are divided as follows:

  • Address Bus: Carries the address. It is unidirectional (from CPU only). If the address bus is 16 bits, it can access $2^{16} = 65,536$ memory locations, indicating where data is stored.
  • Data Bus: Carries the actual data. It is a two-way (bidirectional) pathway. Its size depends directly on the traveling data size (e.g. 1 byte = 8 bits).
  • Control Bus: Carries control and timing signals. The control unit generates control signals through this bus to coordinate all computer activities (e.g. memory read/write strobes).

Computer Memory Hierarchies & Units

Memory is the storage space in the computer where data to be processed and instructions required for processing are stored. Cells are the small divisions making up the memory. The memory hierarchy includes:

  • Registers / Processing Unit: Internal CPU registers working at extreme speeds measured in MIPS (Million Instructions Per Second). Rapid execution rates ($10^6$ instructions/sec = $1\ \mu ext{s}$ per instruction) boost the overall data speed.
  • Cache Memory: A special, high-speed buffer memory that acts as a buffer between RAM and CPU. It speeds up and synchronizes with high-speed CPUs, reducing average access times. Stored in small quantities (KB scale) compared to RAM.
  • Main Memory (RAM/ROM): Primary memory where programs and data are loaded before processing. CPU interacts directly with it. Operates in microsecond range.
  • Secondary Memory: Auxiliary non-volatile memory for permanent storage (e.g. SSD, SD card, pendrive). Slower and cheaper than main memory, operating in millisecond/second ranges. CPU cannot access it directly; contents must first be loaded into main memory.

Memory Subtypes

1. RAM (Random Access Memory): Volatile memory that temporarily stores the active files. Cleared when system shuts down.

  • SRAM (Static RAM): Made of flip-flops, faster than DRAM.
  • DRAM (Dynamic RAM): Made of transistors and capacitors, requires regular charge refreshing.

2. ROM (Read Only Memory): Non-volatile memory, permanently stored on the chips. Used for initial boot-up software (firmware, bootstrap) which does not change. CPU shut down has no effect on it.

Structural Components of a Microcomputer

A microcomputer system contains separate foundational units interacting explicitly over the system buses:

Microcomputer Block Diagram
  • Memory: Mixture of RAM and ROM that stores data, instructions, and intermediate results.
  • Input/Output (I/O): Allows the microcomputer to take input from the outside world or write output to users/peripherals.
  • CPU (Microprocessor): Fetches binary-coded instructions from memory, decodes them into simple actions, and executes them in sequence.
  • Bus: Set of physical wires transferring data, addresses, and control timing signals between components.

Verbatim Chip Classifications (OLF ABCD PT Mnemonic)

A complete microcomputer system uses several auxiliary integrated circuits (ICs) connected to the system bus. They are classified as follows:

  1. Address Latch/Demultiplexer (L): Used where address & data lines are multiplexed (e.g. 8282 latch).
  2. Bus Transceiver/Buffers (B): Protect and drive bus lines (e.g. 8286 transceiver).
  3. Decoder/Chip Detect (D): Generates chip select signals for Peripheral Controller, memory, and I/O chips.
  4. Timers / Counters (T): Programmable interval timers (e.g. 8254) and Interrupt controllers (e.g. 8259).
  5. Peripheral Controllers (P): Programmable Peripheral Interfaces (e.g. 8255).
  6. Clocks & Reset Circuitry (C): Stabilized system startup & clock timing.

Machine Language vs Assembly Language

Machine Language: The lowest level of programming language, consisting of binary instructions (0s and 1s) directly understood by the CPU.

  • Characteristics: Hardware dependent, executes extremely fast, but very hard for humans to read, write, and debug.
  • Example: 10110000 01100001 means move the value 61H (ASCII 'a') to register AL.

Assembly Language: A low-level programming language that uses symbolic names (mnemonics) instead of raw binary codes.

  • Characteristics: Human-readable, CPU specific, and requires an assembler to translate into machine code.
  • Example: MOV AL, 61H followed by ADD AL, 1.
Intel 8085 ASCII Coders: ASCII is the American Standard Code for Information Interchange. It is a 7-bit code with 128 ($128 imes 2^0$) combinations, representing letters, numbers, symbols, or machine commands from 00H to 7FH.

Special Processors

Special processors are designed to handle specific tasks much more efficiently than general-purpose microprocessors. The key types include:

🔌 Coprocessors

A coprocessor is designed to handle specialized functions (such as high-speed floating-point mathematics) many times faster than the primary CPU.

  • Operation: Works in tandem with the main processor, intercepting and executing its own instruction subset.
  • Examples: Intel 8087 (used with the 8086), 80287 (used with the 80286), and 80387 (used with the 80386).
🔄 Input/Output Processors (IOP)

An IOP is a specialized processor with its own local memory that manages data transfer between I/O devices and memory with minimal CPU involvement.

  • Operation: Frees the main CPU from slow I/O overhead by executing dedicated I/O programs.
  • Examples: DMA controllers (e.g. 8237/8257), Keyboard/Mouse controllers, Graphic display controllers, and SCSI controllers.
🔗 Transputers (Transistor Computers)

A transputer is a microchip with local memory and built-in point-to-point communication links for constructing parallel computing networks.

  • Operation: Can operate standalone or connect via serial links to other transputers for inter-processor scaling.
  • Examples: 16-bit T212, 32-bit T425, and floating-point processors like the T800, T805, and T9000 (designed by Inmos in 1980).
📈 Digital Signal Processors (DSP)

DSPs are optimized to process continuous analog signals in digital form in real time using high-speed sampling and computation.

  • Operation: Voltage levels are sampled via an Analog-to-Digital Converter (ADC), processed in the compute engine, and output.
  • Components: Program Memory, Data Memory, Compute Engine, and I/O.
  • Examples: Texas Instruments TMS 320 series (e.g., TMS320C40, TMS320C50).

P2-Q7(d)_cores: Compare the features, architecture, and performance of Single-Core and Multi-Core CPUs. Explain their caching structures. [5]
▼
Sol

CPUs have evolved from single-core processors to multi-core architectures to bypass the physical limitations of clock speed scaling (known as the thermal wall). Multi-core chips deliver higher performance per watt by executing threads in parallel rather than pushing raw clock frequencies.

Single-Core vs. Multi-Core CPU Architectural Caching Comparison

1. Architecture and Cache Structure Comparison:

  • Single-Core CPU: Contains only one execution core (incorporating an ALU, Control Unit, and set of registers). It uses private, dedicated Level 1 (L1) and Level 2 (L2) caches. Because it has only one execution core, it can only run one instruction stream at a time. It handles multitasking through context switching, which introduces scheduling overhead.
  • Multi-Core CPU: Integrates multiple independent CPU cores onto a single silicon chip (die). Each core is fully capable of reading and executing instructions independently. Caching is structured hierarchically to optimize data share speeds: each core has its own private L1 and L2 caches for ultra-fast, local memory accesses, while all cores share a larger, slower L3 cache to coordinate data between threads without needing to access main DRAM.

2. Detailed Comparison of Single-Core and Multi-Core CPUs:

FeatureSingle-Core CPUMulti-Core CPU
Execution CoresExactly one core per processor package.Multiple execution cores (e.g. 2, 4, 8, 16, or more) per processor package.
Parallel ProcessingPerforms pseudo-parallelism (time-shares CPU cycles via software multitasking).True hardware parallel processing (multiple program threads execute simultaneously).
Caching StructureL1 and L2 caches are dedicated solely to the single core. No shared cache exists.Private L1 & L2 caches per core; shared, larger L3 cache across all cores.
Operating FrequencyRequires high clock frequencies to execute tasks faster, creating massive heat.Cores run at lower individual frequencies, maximizing power efficiency.

A **bus system** is a set of shared physical electrical connections (wires or PCB tracks) that connect the MPU to memory and I/O peripherals, allowing them to exchange information. The system bus is divided into three distinct functional buses:

  • Address Bus: Transports memory/port addresses from the processor to memory or peripheral chips. It is unidirectional (goes outward from MPU only). For 8086, it is 20-bit wide (1MB space).
  • Data Bus: Transports instruction codes and operand data between the MPU, memory, and ports. It is bidirectional. For 8086, it is 16-bit wide.
  • Control Bus: Transports commands (RD, WR) and synchronization/acknowledgements signals between MPU and hardware components. It is bidirectional.

NU Exam 3 marks
NU-Q8: What is a bus? Why is the data bus bidirectional? [NU: 2009]
▼
Sol

A **bus** is a shared communication path consisting of physical conductors (wires, optical fibers, or copper traces) used to transfer data, address, or control signals between computer components.

The **data bus** is bidirectional because the microprocessor must perform both **Read** operations (transferring data/instruction codes *from* memory/input devices *to* the MPU registers) and **Write** operations (transferring processed results *from* the MPU registers *to* memory locations or output devices). Having a single bidirectional bus saves pins on the microprocessor package.

Intel 8085 Microprocessor Architecture

The Intel 8085 is a classic 8-bit microprocessor introduced by Intel in 1977 using NMOS technology. It serves as the direct predecessor to the 16-bit 8086. The 8085 operates with an 8-bit data bus and a 16-bit address bus (allowing it to access up to 64 KB of memory), and requires a single +5V power supply to operate at a clock frequency of 3.2 MHz.

8085 Functional Units

The internal architecture of the 8085 consists of the following key functional blocks:

  • Accumulator (A Register): An 8-bit register connected directly to the ALU. It serves as the primary register for arithmetic, logical, and I/O data transfers.
  • Arithmetic and Logic Unit (ALU): Performs 8-bit operations such as addition, subtraction, AND, OR, XOR, complement, and rotations.
  • General Purpose Registers: Six 8-bit registers (B, C, D, E, H, L) that can be accessed individually or as 16-bit register pairs (BC, DE, HL) to hold 16-bit memory pointers.
  • Program Counter (PC): A 16-bit register that stores the memory address of the next instruction to be fetched and executed.
  • Stack Pointer (SP): A 16-bit register used to point to the top of the stack memory. It is automatically incremented or decremented by 2 during push/pop and call/return operations.
  • Temporary Register: An 8-bit register that holds temporary operands during ALU operations; not directly accessible by the programmer.
  • Instruction Register & Decoder: Holds fetched instructions from memory before the decoder translates them into control cycles.
  • Timing & Control Unit: Generates clock cycles and synchronization signals (RD', WR', ALE, status, etc.) to coordinate execution.
  • Interrupt Control Unit: Monitors the 5 hardware interrupt pins (TRAP, RST 7.5, RST 6.5, RST 5.5, INTR).
  • Serial I/O Control: Governs serial data transfers via the SID (Serial Input Data) and SOD (Serial Output Data) pins.

Intel 8085 Pin Configuration & Signal Groups

The 8085 is packaged in a 40-pin Dual In-line Package (DIP). The signals are grouped into the following seven logical categories:

  • Address Bus ($A_15 - A_8$): Pins 21 to 28. Carries the most significant 8 bits of the memory/IO address (unidirectional).
  • Multiplexed Address/Data Bus ($AD_7 - AD_0$): Pins 12 to 19. Carries the least significant 8 bits of the address during state T1 (latched via ALE), and acts as the bidirectional data bus during states T2 and T3.
  • Control & Status Signals:
    • RD' (Pin 31) / WR' (Pin 30): Active-low read/write strobes.
    • ALE (Pin 30): Address Latch Enable. A positive-going pulse that triggers external latches to capture the LSB address from $AD_7-AD_0$.
    • IO/M' (Pin 34): High selects I/O operations; Low selects memory operations.
    • S0 (Pin 29) / S1 (Pin 33): Machine cycle status indicators (e.g. 00=HALT, 01=WRITE, 10=READ, 11=FETCH).
  • Power Supply: VCC (+5V, Pin 40) and VSS (Ground, Pin 20).
  • Clock Signals:
    • X1, X2 (Pins 1, 2): Connected to a crystal resonator to set the internal clock generator frequency (internally divided by 2).
    • CLK OUT (Pin 37): Output clock signal for system synchronization.
  • Interrupts & Externally Initiated:
    • Hardware interrupts: TRAP (Pin 6), RST 7.5 (Pin 7), RST 6.5 (Pin 8), RST 5.5 (Pin 9), INTR (Pin 10).

  • DMA Signals: HOLD (Pin 39) requests bus access; HLDA (Pin 38) indicates CPU has released buses.
  • Serial I/O: SID (Pin 5) inputs serial data (loaded via RIM); SOD (Pin 4) outputs serial data (written via SIM).

Instruction Queue Operation:

The 8086 BIU contains a 6-byte FIFO (First-In First-Out) queue that pre-fetches instructions from memory while the EU executes previously fetched instructions.

  • The BIU automatically fetches bytes from memory whenever the queue is not full (has 2+ empty bytes).
  • Instructions enter the queue from the TOP (high address) and EU reads from the BOTTOM (FIFO order).
  • Queue is FLUSHED when a branch instruction (JMP, CALL, RET) changes IP — fetched bytes are discarded.
  • Queue depth of 6 bytes typically holds 2–3 complete instructions (since average instruction ≈ 2–3 bytes).

How Pipelining Saves Time:

Without Queue: Time for N instructions = N × (Fetch_time + Execute_time)
With Queue: Time for N instructions ≈ Fetch_time_1 + N × max(Fetch_time, Execute_time)

Since BIU fetches while EU executes, the system effectively hides the memory fetch latency. When execute time > fetch time, BIU stays ahead and queue stays full. When fetch time > execute time, EU occasionally waits — but still faster than non-pipelined.

Speedup ≈ 30–40% compared to non-pipelined sequential operation

Intel 8086 Microprocessor Internal Architecture (BIU & EU)

  • Instruction Fetching: Fetches instructions from memory and stores them in the 6-byte instruction queue.

  • Instruction Pointer (IP): Holds the 16-bit offset of the next instruction code byte to be fetched.
  • Address Generation: Contains a 20-bit adder that computes the physical memory address using the formula: \( \text{Physical Address} = \text{Segment Register} \times 16 + \text{Offset} \).

2. Execution Unit (EU):

The EU is responsible for decoding and executing the pre-fetched instructions. It does not connect directly to the system buses; it relies on the BIU for data transfer. Its main components include:

  • Control Circuitry & Instruction Decoder: Decodes instruction codes retrieved from the BIU queue and coordinates internal registers to execute the operation.
  • Arithmetic Logic Unit (ALU): A 16-bit logic core that performs arithmetic (add, subtract, increment) and logical (AND, OR, XOR) operations.
  • FLAG Register: A 16-bit status register containing 9 active flags (6 Status Flags: CF, PF, AF, ZF, SF, OF; and 3 Control Flags: TF, IF, DF) that record the results of ALU operations and direct execution flows.
  • General Purpose Registers (AX, BX, CX, DX): 16-bit registers used for calculations (each can be split into 8-bit registers like AH/AL).
  • Pointer and Index Registers: SP (Stack Pointer), BP (Base Pointer) facilitate stack accesses, while SI (Source Index) and DI (Destination Index) hold offsets for memory addressing and string operations.

The 8086 is a 16-bit microprocessor with a 20-bit address bus and a 16-bit data bus ($D_0 - D_{15}$). Memory is organized physically as two 8-bit banks: the Even Bank (Low Bank) containing even-addressed bytes, and the Odd Bank (High Bank) containing odd-addressed bytes. To select banks, the 8086 uses address line $A_0$ and the active-low Bus High Enable signal ($BHE'$). This architecture allows transferring either an 8-bit byte or a 16-bit word in a single bus cycle when aligned.

8086 Even/Odd Memory Banks & Data Transfer

Data transfers fall into four distinct cases based on alignment and operand size:

  • Case 1: Even Address Byte Transfer (8-Bit from even address): The byte resides in the Even Bank. The CPU asserts address line $A_0 = 0$ (enabling the Even Bank) and $BHE' = 1$ (disabling the Odd Bank). Data is transferred over lower bus lines $D_0 - D_7$ in 1 bus cycle. Example: MOV AL, [2000H].
  • Case 2: Odd Address Byte Transfer (8-Bit from odd address): The byte resides in the Odd Bank. The CPU asserts $BHE' = 0$ (enabling the Odd Bank) and $A_0 = 1$ (disabling the Even Bank). Data is transferred over upper bus lines $D_8 - D_{15}$ in 1 bus cycle. Example: MOV AL, [2001H].
  • Case 3: Even-Aligned Word Transfer (16-Bit from even address): The 16-bit word occupies two consecutive bytes starting at an even address (one byte in Even Bank, one in Odd Bank). The CPU asserts $BHE' = 0$ and $A_0 = 0$, enabling both banks simultaneously. The entire 16-bit word is transferred over data lines $D_0 - D_{15}$ in a single bus cycle. Example: MOV AX, [2000H].
  • Case 4: Odd-Aligned/Misaligned Word Transfer (16-Bit from odd address): The word starts at an odd address and spans across a word boundary. The CPU cannot access it in one cycle and requires two bus cycles:
    1. Cycle 1 (Odd Byte): Transfer the lower byte from the odd address via upper data lines $D_8 - D_{15}$ ($BHE'=0, A_0=1$).
    2. Cycle 2 (Even Byte): Transfer the higher byte from the next (even) address via lower data lines $D_0 - D_7$ ($BHE'=1, A_0=0$).

A **bus** is a collection of parallel conducting lines or wires that acts as a shared communication path to transfer binary signals (data, address, and control info) between the microprocessor, memory, and peripheral I/O interfaces.

The shared lines are grouped together into three distinct buses collectively known as the **System Bus**:

    • MOV DS, AX: Copies AX into DS.
    • MOV SI, DI: Copies DI into SI.
    • Invalid: MOV ES, DS (Not allowed: segment to segment transfer).
    • Invalid: MOV BL, DX (Not allowed: mixed size mismatch).
    • Invalid: MOV CS, AX (Not allowed: CS segment register cannot be the destination).
  • Immediate Addressing Mode: Data immediately follows the opcode stream inside the instruction.
    • MOV AL, 15H: Copies immediate byte 15H into AL.
    • MOV AX, 1234H: Copies immediate word 1234H into AX.
    • MOV [BX], 55H: Copies immediate byte 55H into memory at DS:BX.

    • Invalid: MOV DS, 1000H (Not allowed: segment registers cannot be loaded directly with immediate data).

    • MOV CX, [1234H]: Copies 16-bit word from DS:1234H into CX.

    • MOV AX, [SI]: Copies word from DS:SI into AX.

    • MOV [BP + 100H], CX: Copies word CX into stack SS:BP + 100H.
    • Invalid: MOV AL, [AX + 5] (Not allowed: AX cannot be used as base register).
  • Indexed Addressing Mode: Effective address is Index Register (SI/DI) + displacement.
    • MOV AL, ARRAY[SI]: Copies byte from DS:ARRAY + SI into AL.
    • MOV [DI + 20H], AX: Copies word AX into DS:DI + 20H.
    • Invalid: MOV AL, [CX + 4] (Not allowed: CX cannot be used as index register).
  • Based Indexed Addressing Mode: Effective address is Base Register (BX/BP) + Index Register (SI/DI).
    • MOV AL, [BX][SI]: Copies byte from DS:BX + SI into AL.
    • MOV [BP][DI], DX: Copies word DX into stack SS:BP + DI.
    • Invalid: MOV AL, [BX][BP] (Not allowed: cannot combine two base registers).
    • Invalid: MOV AL, [SI][DI] (Not allowed: cannot combine two index registers).
  • Based Indexed with Displacement Addressing Mode: Effective address is Base Register + Index Register + displacement.
    • MOV AH, [BX][SI] + BETA: Copies byte from DS:BX + SI + BETA into AH.
    • MOV [BP + 4][DI], CX: Copies word CX into stack SS:BP + DI + 4.

Below are the verbatim details and constraints for the exchange, shift, rotate, and clear direction instructions:

The 8086 microprocessor uses a variable-length instruction format ranging from 1 to 6 bytes. This compact encoding minimizes program size and bus overhead.

An **Addressing Mode** defines the scheme or method by which the instruction specifies the location of the operand(s) (either data constants, internal registers, or physical memory locations) to be processed.

Core 8086 Addressing Modes with Examples:

1. Immediate Addressing Mode:

  • The operand data is a constant value embedded directly within the instruction opcode stream.
  • Example: `MOV AX, 1234H` (loads the immediate 16-bit value 1234H into AX).

2. Register Addressing Mode:

  • The operand resides inside one of the internal CPU registers. No memory accesses are required.
  • Example: `MOV AX, BX` (copies 16-bit contents of BX into AX).
  • Example: `ADD DL, CL` (adds the byte contents of CL to DL).

3. Direct Addressing Mode:

  • The 16-bit effective address (displacement offset) of the memory operand is written directly inside the instruction brackets.
  • Example: `MOV AX, [2000H]` (loads AX from memory offset 2000H in the Data Segment: `Physical Address = DS × 10H + 2000H`).

4. Register Indirect Addressing Mode:

  • The effective offset address of the memory operand is held in a base register (`BX` or `BP`) or an index register (`SI` or `DI`).
  • Example: `MOV AX, [BX]` (copies data from memory offset pointed to by BX in DS into AX).

5. Register Relative Addressing Mode:

  • The offset address is computed as the sum of a register (`BX`, `BP`, `SI`, `DI`) and an 8-bit or 16-bit displacement value.
  • Example: `MOV AX, [BX + 4]` (copies data from offset `BX + 4` in DS into AX).

  • The offset address is computed by summing a base register (`BX` or `BP`) and an index register (`SI` or `DI`).
  • Example: `MOV AX, [BX][SI]` (copies data from offset `BX + SI` in DS into AX).

7. Relative Base Indexed Addressing Mode:

  • The offset address is computed as the sum of a base register, an index register, and a displacement constant.
  • Example: `MOV AX, [BX + 2][SI]` (offset is `BX + SI + 2`).

Q3(a): Why does the 8086 support byte-addressable memory despite being a 16-bit microprocessor?
▼
Sol

The 8086 is a 16-bit microprocessor with a 16-bit data bus, meaning it can transfer 16 bits (one word = 2 bytes) in a single bus cycle. However, it supports byte-addressable memory for the following critical reasons:

1. Memory Organisation:

The 8086's 1 MB memory space (2²⁰ = 1,048,576 locations) is organised as two separate banks of 512 KB each:

  • Even Bank (Low Bank): Connected to data bus lines D0–D7, addressed at even addresses (A0=0).
  • Odd Bank (High Bank): Connected to data bus lines D8–D15, addressed at odd addresses (BHE'=0).

P3-Q5(c): What is cache memory? How many address lines required to address a memory of 32 KB?
▼
Sol

**Cache memory** is a very small, extremely fast semiconductor memory located physically between the CPU and the main memory (RAM). It stores copies of frequently accessed data and instructions from the main memory. When the CPU needs data, it checks the cache first. If found (a cache hit), access is extremely fast; if not (a cache miss), the CPU retrieves it from RAM. This significantly reduces average memory latency, preventing CPU wait-states.

  • Locality of Reference: Cache works because programs exhibit temporal locality (re-accessing same variables) and spatial locality (accessing adjacent array data).
  • Speed levels: Typically constructed using fast Static RAM (SRAM), which operates at CPU speeds, unlike the slower Dynamic RAM (DRAM) used for main memory.

Address Lines Calculation for 32 KB Memory:
We determine the address lines using the capacity formula $N = 2^x$ (where $N$ is capacity in bytes, and $x$ is the number of address lines):

32 \text{ KB} = 32 \times 1024 \text{ bytes} = 32,768 \text{ bytes}
32 \text{ KB} = 2^5 \times 2^{10} \text{ bytes} = 2^{15} \text{ bytes}

Since $N = 2^{15}$, the exponent is $x = 15$. Thus, **15 address lines** ($A_0 - A_{14}$) are required to uniquely address a memory of 32 KB.

NU-Q6: Explain the concept of segment memory. What are its advantages? [NU: 2012, 2014]
▼
Sol

In 8086 systems, **segmented memory** organizes the physically available memory (1MB) into smaller logical blocks called segments. Each segment can be up to 64KB in size, pointed to by a 16-bit segment register (CS, DS, SS, ES) in the Bus Interface Unit (BIU). The physical address is calculated by shifting the segment value left by 4 bits (multiplying by 16) and adding a 16-bit offset address.

Segments can be overlapped (sharing physical memory locations) or non-overlapped (completely isolated).

  • Allows 1MB memory spacing: Permits addressing 1MB ($2^{20}$ bytes) of memory using 16-bit address offsets, keeping instruction sizes small.
  • Code, Data, and Stack isolation: Placing different portions of a program in separate segments allows memory segmentation protection to prevent errors.
  • Program Relocation: Allows programs and their data to be relocated dynamically into different parts of memory each time they are executed without altering offset references.

🔄 Direct Memory Access (DMA) & 8237

💡 Topic Shortcut & Exam Tips

  • DMA Handshake: Peripheral asserts HOLD → CPU finishes current instruction → CPU asserts HLDA, releasing buses.

Direct Memory Access Overview

Direct Memory Access (DMA) is a data transfer technique where an external device transfers data directly to or from memory without going through the CPU. The DMA controller (e.g. Intel 8237 / 8257) requests control of the buses from the CPU using the HOLD pin. When granted via the HLDA pin, the DMA controller takes charge of the address and control lines, enabling extremely fast byte-level or block-level transfers between I/O peripherals (such as disk drives) and system memory.

Paper 2 4 marks
P2-Q5(c): What is DMA? Describe modes of data transfer and operation of DMA controller.
▼
Sol

DMA (Direct Memory Access) is a data transfer technique that allows peripherals to transfer data directly to/from memory WITHOUT CPU involvement, freeing the CPU for other tasks.

Without DMA: CPU controls every byte transfer (IN/OUT instructions) — wastes CPU cycles.

With DMA: DMA controller takes over the bus, transfers blocks of data at full bus speed.

DMA Transfer Rate = Bus Speed (typically 5–200 MB/s) without CPU overhead

Modes of DMA Data Transfer:

  • 1. Single Transfer (Cycle Steal) Mode: DMA transfers ONE byte/word per bus request. CPU bus is 'stolen' for one cycle. CPU continues between steals. Minimal CPU disruption but slower overall transfer.
  • 2. Block Transfer (Burst) Mode: DMA requests bus, transfers an ENTIRE BLOCK of data (predetermined count) without releasing bus. CPU is halted for the entire block — fastest for large transfers (disk, video frame).
  • 3. Demand Transfer Mode: DMA transfers continuously as long as the peripheral has data. Bus released when peripheral is not ready (DREQ deasserted). Balance between speed and CPU access.
  • 4. Cascade Mode: Multiple DMA controllers connected — one acts as master, others as slaves. Expands number of DMA channels.

DMA Transfer Process:

  • Step 1: Peripheral requests DMA transfer via DREQ (DMA Request) signal to DMAC.
  • Step 2: DMAC asserts HOLD to CPU — requests bus mastership.
  • Step 3: CPU completes current bus cycle, asserts HLDA (Hold Acknowledge), tri-states its buses.
  • Step 4: DMAC takes control: asserts DACK to device, generates memory address, controls RD'/WR'.
  • Step 5: Data transferred directly between device and memory at bus speed.
  • Step 6: DMAC releases HOLD when complete — CPU resumes with HLDA deasserted.

A ladder diagram is a graphical programming language used to program Programmable Logic Controllers (PLCs). It is structured to resemble electrical ladder schematics used in industrial control circuits.

  • Power Rails: Two vertical lines bounding the diagram. The left rail represents the positive voltage source ('Hot'), and the right rail represents the neutral or return path ('Common').
  • Rungs: Horizontal lines connecting the two rails. Each rung represents a single line of logic which is scanned sequentially from top to bottom, executing contacts from left to right.
  • Normally Open (NO) Contact (-| |--): Represents an input switch or sensor. It acts as an open circuit in its default state. When the associated input is energized, the contact closes, allowing power to flow through.
  • Normally Closed (NC) Contact (-|/|--): Represents a default-closed switch or sensor. It conducts power by default. When the associated input is energized, the contact opens, interrupting power flow.
  • Output Coil (--( )--): Represents the load, actuator, relay, or internal bit being controlled. When a path of closed contacts completes the connection from the left rail to the coil, it becomes energized (ON).
  • Branch: Parallel connections on rungs used to implement logical 'OR' operations (multiple paths for power flow to reach the output).
  • Special Function Blocks: Predefined logic blocks representing timers, counters, comparators, math blocks, and data transfer functions.

Implementing an Exclusive-OR (X-OR) Gate in Ladder Logic:

The Boolean equation for an X-OR gate is: \( Y = A\bar{B} + \bar{A}B \). This means Output \( Y \) is active if Input \( A \) is active AND Input \( B \) is inactive, OR if Input \( A \) is inactive AND Input \( B \) is active.

\begin{array}{rccccc} & \text{Carries:} & 0001\ 0101\ 1111\ 1110 & \\ & \text{AX:} & 0011\ 0100\ 1111\ 0101 & (34F5H) \\ + & \text{BX:} & 1001\ 0101\ 1110\ 1011 & (95EBH) \\ \hline & \text{Result:} & 1100\ 1010\ 1110\ 0000 & (CAE0H) \end{array}

  • SP / BP / SI / DI: Offset pointers. SP is Stack Pointer; BP is Base Pointer; SI is Source Index; DI is Destination Index.
  • CS / DS / SS / ES: Segment registers (Code, Data, Stack, Extra segment bases).
  • IP: Instruction Pointer (Program Counter). Holds instruction offset.
  • FLAGS: Contains Carry (CF), Parity (PF), Auxiliary Carry (AF), Zero (ZF), Sign (SF), Trap (TF), Interrupt (IF), Direction (DF), Overflow (OF).

🔌 8086 Control Bus Signals

  • ALE: Address Latch Enable (HIGH indicates address bus is active).
  • BHE': Bus High Enable (LOW activates high data bank D8–D15).
  • M/IO': Memory (HIGH) or I/O (LOW) select.
  • RD' / WR': Read/Write active-LOW command lines.
  • DEN' / DT/R': Data Enable (activates transceivers) and Data Transmit/Receive direction control.
  • MN/MX': Minimum mode (+5V) or Maximum mode (0V - uses 8288 bus controller).
  • READY: Introduces wait states if LOW (synchronizes slow memory).

💾 Addressing Modes Summary

  • Immediate: Constant operand in instruction: MOV AX, 1234H
  • Register: Data in registers: MOV AX, BX
  • Direct: Offset given directly: MOV AX, [2000H]
  • Register Indirect: Pointer in BX/SI/DI: MOV AX, [BX]
  • Register Relative: Pointer + displacement: MOV AX, [BX+4]
  • Base Indexed: Base + Index: MOV AX, [BX][SI]
  • Relative Base Indexed: Base + Index + displacement: MOV AX, [BX+2][SI]

⚙️ 8255 PPI Port Control Word

  • Control Word Format (Mode 0 configuration):
  • Bit 7: 1 = I/O Mode active (0 = BSR mode).
  • Bit 6-5: Port A Mode Selection (00 = Mode 0).
  • Bit 4: Port A Direction (1 = Input, 0 = Output).
  • Bit 3: Port C Upper Direction (1 = Input, 0 = Output).
  • Bit 2: Port B Mode Selection (0 = Mode 0).
  • Bit 1: Port B Direction (1 = Input, 0 = Output).
  • Bit 0: Port C Lower Direction (1 = Input, 0 = Output).
  • Example control word 90H: Port A=Input, Port B=Output, Port C=Output.

🔩 8254 Timer Control Word

  • Control Register Format:
  • Bit 7-6: Select Counter (00=C0, 01=C1, 10=C2, 11=Read-Back).
  • Bit 5-4: Read/Write Mode (00=Latch, 01=LSB, 10=MSB, 11=LSB then MSB).
  • Bit 3-1: Timer Operating Mode (000 to 101, Modes 0–5).
  • Bit 0: Count format (0 = Binary, 1 = BCD).
  • Modes: Mode 0 (Interrupt on count), Mode 1 (Programmable Monostable), Mode 2 (Rate Generator), Mode 3 (Square Wave Generator), Mode 4 (Software Triggered Strobe), Mode 5 (Hardware Triggered Strobe).

📈 Industrial PLC Logic Cycle

  • 1. Input Scan: Reads the state of physical inputs (limit switches, sensors) and copies them into the input image register.
  • 2. Program Execution: Executes the logic program (e.g. Ladder Logic) line by line, updating intermediate states.
  • 3. Output Scan: Copies the updated output states from the output image register to physical outputs (coils, indicators).
  • Cyclical scan time: Typically takes 1 to 20 milliseconds, repeating continuously.
